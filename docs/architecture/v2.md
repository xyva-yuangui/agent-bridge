# Agent Bridge v2 architecture

Agent Bridge is a local-first, on-demand coordinator. It does not run a daemon
or network listener. The CLI and MCP entry point open a local SQLite database,
perform a bounded operation, optionally request a short dispatcher burst, then
exit.

```text
CLI / MCP / TUI
       |                 host adapters -> session-card consumers
BridgeService -> SQLite WAL -> transactional outbox -> dispatcher
       |                 notification channels -> OS helper / degraded result
       +-> migrations, state machine, audit events
```

`Store` owns migrations, WAL transactions, and integrity checks. `BridgeService`
owns authorization and task transitions. The dispatcher claims committed outbox
records and records delivery evidence; a launched process is never an
acknowledgement. Host adapters only edit owned configuration and emit atomic
session cards. Native helpers receive bounded JSON protocols and never execute
task text as a shell command.

## Capability levels

The shipped integrations for Codex, Claude Code, Reasonix, and ZCode are
versioned session-card templates. Their actual status is reported by
`bridge setup status`: a detected, healthy integration can acknowledge cards;
otherwise Agent Bridge reports `terminal-fallback`. This is deliberately more
conservative than claiming an unverified native panel.

## Persistence and recovery

Data lives under `~/.agent-bridge` (or `AGENT_BRIDGE_HOME`). SQLite WAL requires
a local filesystem; network shares and consumer-sync folders are unsupported.
If a host is unavailable, inspect `bridge status`, `bridge inbox`, and
`bridge doctor`; no background process must be restarted. Setup receipts limit
repair and uninstall to files and PATH entries Agent Bridge owns.

## Adapter contract

Add adapters through the canonical registry, not by parsing arbitrary host
configuration. An adapter must declare a stable host identity, capabilities,
managed configuration, an exact consumer entry point, task-card containment,
and an acknowledgement proof. Keep an integration manifest in both the source
template directory and the packaged resource surface.
